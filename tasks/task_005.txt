  ```ini
  exclude = .git,__pycache__,build,dist
  ignore = E203,W503  # Black compatibility
  per-file-ignores =
      __init__.py:F401,F403
  ```

  ```toml
  [tool.black]
  line-length = 100
  target-version = ['py38']

    | buck-out
    | build
    | dist

  '''
  ```

  ```toml
  [tool.isort]
  profile = "black"
  line_length = 100
  ```

# Manual Linting Fixes Implementation

## Systematic Process
- Run comprehensive linting after automated formatting:

  ```bash
  flake8 crystal_symmetry/ --max-line-length=88 --format=json > linting-errors.json
  ```
- Create Python script to group and prioritize remaining errors:
  ```python
  # Example parsing script
  import json
  with open('linting-errors.json') as f:
      errors = json.load(f)
  
  by_type = {}
  for error in errors:
      error_code = error['code']
      if error_code not in by_type:
          by_type[error_code] = []
      by_type[error_code].append(error)
  ```
- Create tracking tickets for each major error category

## Prioritization Strategy
- Critical: Errors affecting correctness or security (e.g., undefined names, risky practices)
- High: Code smells that affect maintainability (e.g., complexity, duplicate code)
- Medium: Documentation issues (missing docstrings, incorrect formats)
- Low: Stylistic issues not caught by automated formatting

## Common Error Patterns
- For `E501` (line too long): Refactor long expressions into multiple variables
- For `F841` (unused variables): Remove or prefix with underscore
- For `C901` (too complex): Break function into smaller, focused functions
- For `E711/E712` (comparison to None/boolean): Use `is None` or `is True` instead
